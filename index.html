The workings

Everything above answers one question: where should we eat. Everything below answers a different one — how the page that answers it is put together, and what it got embarrassingly wrong on the way.

Where it comes from

One Google Sheet, seven columns, filled in by hand after eating. A build script pulls it as a spreadsheet file, asks OneMap — Singapore’s national mapping service — where each address is, then asks again how long it takes to get there from each house, on foot and by public transport. That produces four small JSON files. A second script inlines Leaflet and those files into a single index.html, which GitHub Pages serves. A scheduled job re-runs the whole thing every Monday morning, so the page does not rot if nobody touches it.

There are three ways to update it, in increasing order of permanence: Pull from sheet re-reads the sheet in your browser and changes only what you are looking at; a Refresh button on GitHub rebuilds and republishes without a terminal; ./update.sh does it locally.

The state of things

Counted from the data on this page, not typed in — so they cannot quietly go stale.

Six things that were wrong

  1. The map used to carry its own map. About two hundred basemap tiles were baked into the page as base64 text — three megabytes of it — and the map was fenced to exactly the area they covered.

    The reason was real, and then stopped being real: this page was first built as a Claude Artifact, where a strict security policy blocks every request to another host, so the tiles had to travel inside the file. It then moved to GitHub Pages, where nothing blocks a tile server, and nobody rechecked the assumption for weeks. Live tiles now: the page dropped to a quarter of a megabyte and pans anywhere in the world.

  2. A restaurant 43 metres from Chinatown station was reported as a 41-minute walk from Farrer Park.

    Nearest-station was being computed against the seven stations drawn on the map. That is correct while every place is in the neighbourhood and silently wrong the moment one is not. The arithmetic was never the bug; the candidate set was. The page now carries the entire network.

  3. Six ratings appeared to have been typed into the wrong column. None of them had.

    An empty spreadsheet cell that carries formatting is written self-closing — <c r="E5" s="1"/> — with no closing tag of its own. The reader matched only paired tags, so an empty cell ran on and swallowed the value of the cell beside it. Every row with a blank Minus had its rating eaten. Worse than the bug was the helpful fix built on top of it, which moved stray numbers back into place and so made a parser fault look like a human habit — and printed six warnings a build telling the owner to correct a sheet that was already correct.

  4. On a phone the whole page was laid out 980 pixels wide and shrunk to fit.

    It had shipped without a viewport declaration, because the Artifact host used to supply the surrounding document and Pages supplies nothing. Desktop browsers cannot reproduce it, which is why it survived every screenshot.

  5. Distance is not time. Four kilometres to Chinatown reads as far away. It is seventeen minutes on the North East line.

    The column now shows measured travel time and names the mode, because a bare number of minutes is useless if you cannot tell whether you are walking it. One place on this list is quickest by bus.

  6. Leaflet ships a Ukrainian flag inside its own attribution string. Naming the attribution ourselves keeps the credit and drops the flag.

Things it deliberately does not do

  • No analytics, no cookies, no tracking, no fonts phoning home beyond Google’s stylesheet. Nothing is recorded about you reading this.
  • The houses are anchors for every measurement on the page, but no postal code or block number appears anywhere in the source — only coordinates. That was a decision, and it is enforced on every build.
  • It never guesses. A place it cannot route keeps a straight-line estimate and says so in italics; a rating in the wrong column reads as unrated rather than being quietly moved.

How it knows it still works

Two entirely separate readers parse the same sheet — Python over the spreadsheet file, JavaScript over the CSV export — and every build compares them column by column. That cross-check is the only reason problem three above was findable at all: the names and addresses lined up perfectly while the values beside them were shifted one place left.

A smoke test then runs the built page’s own code against a stubbed browser and fails the build if the map never gets a view, the table never gets written, or the Pull from sheet button cannot complete a round trip. Every fix listed above arrived with a test, and every test was checked by putting the bug back and watching it fail.
